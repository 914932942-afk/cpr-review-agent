目标覆盖与边际成本感知的
Agent 工具调度与停止决策

让 Agent 根据本次检查范围、已有证据和剩余预算，决定哪些工具需要运行、哪些可以复用，以及何时应该停止。

已实现：在冻结的 M1 / M2 / M3 基础上，增加有约束的 DAG 路径选择。M4 的收益是减少不必要的计算、清楚表达检查范围；没有宣称提高 CPR 分类准确率。M5 仍为基线。

用户目标M4 实际执行结果边界

算法改进体现在哪里

有约束的最小边际成本覆盖

先筛掉不能覆盖本次目标、缺少依赖或超出预算的路径，再选择“新增目标覆盖 / 边际成本”最高的合法路径。已验证的缓存依赖成本按 0 计，仍需重新生成的新结果不会误算为缓存。

来源约束的复用与停止

复用必须属于服务器绑定报告的实际依赖闭包，并匹配视频、模型版本和同一骨架来源。覆盖完成、仅复盘、工具失败、预算不足或没有独立信息时，输出明确停止原因。

选择：max 新增目标覆盖数量 / 预计新增耗时
约束：完整覆盖本次目标 ∧ 已批准路径 ∧ 依赖齐备 ∧ 来源一致
预算：预计耗时上界 + 8 秒收尾余量 ≤ 剩余时间

成本参数来自 6 条真实历史执行记录，包含重复样片；中位耗时用于排序，实际预算上界采用观测最大值 × 1.25，较长视频只向上放大姿态成本。Bootstrap 分位数作为诊断保存，不构成总体运行时间保证，也不是本版主要改进来源。

为什么轻量路径不会漏报目标类别

冻结的融合规则会独立保留已达可靠性门槛的非 RGB 类别；M2 的范围约束又保护了这些决定。因此，对 3 / 4 / 8 / 11 这 4 类，骨架分数、阈值和最终判断可与完整流程保持一致。

跳跃按压、位置改变等类别仍受其他约束影响，不能仅因它们属于“身体动作”就跳过 RGB。M4 对这些目标继续选择完整路径。

实际收益与取舍

只检查认证骨架范围4 次调用3 次，省去 RGB

虚拟请求集 = 每段原有视频的 11 个单类别目标 + 1 个全类别目标；不是新增 312 段视频，也不是实际执行这么多次 GPU 推理。估计值来自历史耗时模型。

取舍：先小范围、再马上扩大范围，累计是 5 次工具调用，比一开始全量检查的 4 次多一次结果汇总。若本来就需要全量，直接选择 All categories 更合适。当前优化针对本次明确目标，不预测用户未来一定会扩展。

演示实测：小范围约 88.0 秒，追加范围约 37.7 秒；另一段全量视频约 131.5 秒。样片与运行时机不同，不将这组数值当作受控速度提升比例。结果汇总仍走现有 worker，进程启动开销尚未单独优化。

决策模式：有限 Plan & Execute，执行后按状态重评估。LangGraph 仍为 12 节点；图版本升级为 cpr-review-12-v0.7-routing。M4 是轻量确定性优化模块，DeepSeek 本次关闭。

  • 243 项当前版本工程测试、22 项策略 / worker 检查通过。导入路径、范围声明、预算、合法动作、缓存授权和不可覆盖产物分别验证。
  • 真实 HTTP 验收完成小范围、范围扩大和全量 3 次分析，成功执行 9 次视觉工具；另通过界面实际点击扩展，再执行 2 次缺失工具。
  • 解释、总结和对已覆盖不确定项的复核请求不重跑视觉。仅复盘未覆盖类别时返回未检查，不输出虚假的阴性结论。

首次真实联调的 worker 导入失败记录保留；修复后重新建立匹配当前版本的会话并完成验收，没有把旧失败产物改标成成功。严格按用户选中的报告复用，不自动把另一个最新报告替换为讨论来源。
