## 本机启动

```powershell
Set-Location -LiteralPath 'E:\998\CPR+AGENT\CODE'

```

打开 http://127.0.0.1:8000 。当前本地 `.env` 已选择 `CPR_VISION_MODE=real`，ML Python 指向独立的 `ml` 环境。FastAPI 使用 `.venv`，不把 PyTorch 安装到 Web 环境。必须单进程运行。

1. 上传一段**完整的单视角 CPR 训练视频**。
2. 展开 **Focus** 选择复盘类别，点击 **Start review**；也可向右侧助手发送请求，必要时在确认表单中明确目标。

## 大模型的两种模式

在项目根目录 `.env` 中配置（Key只保存在后端，不进入前端或版本库）：

```dotenv
CPR_LLM_MODE=disabled
CPR_LLM_TIMEOUT_SECONDS=8
DEEPSEEK_API_KEY=在本机填写真实Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

- **disabled：当前阶段。** 不外呼、不验证Key、不自动探测余额；结构化目标和表单可正常使用。
- **deepseek：按需启用。** 将开关改为 `deepseek` 并重启，再提交一个新的文字请求。仅填写Key不会启用。结构化按钮绕过N02目标解析；deepseek模式下，N11解释组织仍可能产生模型调用。

`Settings.from_env()` 支持直接读取本项目 `.env`，也适用于PyCharm启动；同名进程环境变量优先。`start.ps1` 会载入 `.env` 的 CPR_/DEEPSEEK_ 项。配置采用字面值，不做脚本或变量展开。

N02要求JSON输出并按 `ReviewGoal` 校验，只接受白名单意图和11类标签。缺少Key、鉴权/余额/限流错误、超时、输出截断或不合法时进入N03表单；不把错误文本当作回答。连续3次调用失败后熔断60秒，期间直接回表单；单次调用不自动重试。偏好保存/忘记仍通过明确的界面按钮操作，不执行大模型生成的记忆写入。

传给模型的内容限于当前文字、最近最多4个已确认目标、显式关注类别及是否绑定视频；不发送视频、帧、文件路径、逐视频真实标签或识别分数。目标解析的结果和降级码写入回执，用于恢复与追踪；Key、请求头、供应商错误正文不入库。健康检查只显示模式、是否配置Key、连接是否验证等状态，不发探测请求。

调用代码、模拟测试与独立8006入口的真实联调已验证。项目默认模式仍保持 `disabled`，启用步骤和调用边界见上方真实联调说明。

## 复盘证据与历史恢复

左侧的 **Your practices** 从本地 SQLite 读取最近50个会话；选择会话即可恢复视频与保存结果；trace仅在Technical details中显示。**Review history** 列出该会话的各次请求，包含完成、失败和等待状态；每页20条，可继续加载旧记录。清空工作区视图只清理浏览器选择，不删除数据库记录。

**Show selected focus** 和类别卡片的 **Explain** 展示所选类别的保存结果；原始分数和阈值在 **How this was assessed** 中按需展开。**Make a recap** 仅汇总当前显示的类别范围。两者复用兼容的已有分析，不额外执行视觉模型。分支分数与阈值的比较不能完整解释最终融合判定，界面对此单独说明。

打开证据详情时重新核验原视频、模型清单及原始结果文件的绑定与哈希。源文件缺失或发生变化时仍可查看历史摘要，但证据详情显示不可用；不补造数据，也不把历史快照标为当前有效结果。旧报告可动态读取证据，无需改写报告。旧模型版本的会话保留浏览入口，新请求需要建立当前版本会话。

接口：`GET /api/workspaces`、`GET /api/sessions/{id}/history?limit=20&before_turn_id=...`、`GET /api/reports/{id}/evidence`。历史接口返回受控展示字段，证据接口只读取，不触发推理或外部模型。

- 输入不超过 50 MiB；8–900 帧、最长45秒、最大3840×2160像素面积，尺寸恒定、可完整解码。初版仅处理整个上传文件；不支持设置起止时间后暗中分析全片。
- 推荐使用现有 CPR-Coach ch0 公开短片。任意机位、非 CPR 内容及多人遮挡场景没有泛化保证；预检不等于自动确认 CPR 内容有效。
- 默认8000入口的 `video.analyze` 是一个真实工具，内部运行冻结v15。8001基线和8002的M1入口执行四个独立真实工具，具体见对应实现说明。
- 11个支持标签的输出区分 `model_flagged`、`not_flagged` 和 `not_evaluated`。未检出不等于动作正确；分数未校准，不展示为医学概率。
- 不输出精确错误起止时刻、按压深度、实际测量的 BPM。`verify` 复用同一分析，不冒充独立二次验证。
- M1改进已接入后续各入口。M2改进在8008独立入口生效，8007仍保留M2基线；M3校准、M4成本收益调度、M5预算化采样仍需实现和验收。
- 本地单用户演示；非公网、多用户或生产部署。

## 持久化与可靠性

业务数据在 `data/business.sqlite3`；图状态在 `data/checkpoints.sqlite3`。原视频在 `data/media/`。每个工具执行及其尝试在 `data/analysis/<execution_id>/<attempt>/` 保存原始JSON、特征、预检、进程日志和回执。日志在 `data/logs/runtime.jsonl`，事件和trace ID可从API查询。

单GPU队列；工具进程持有GPU文件锁。取消、服务超时和工具超时会终止计算，不提交待完成结果。优雅停机保留检查点；重启时完整回执经哈希验证后复用，部分尝试保留并另建目录重试。硬中止留下的孤儿进程仍持有GPU锁；锁冲突会明确失败，不并行抢占。没有宣称分布式 exactly-once。

结果复用严格按当前clip、视频SHA256、bundle SHA256和原始结果文件SHA256匹配；旧版本、缺失/改变的文件不会作为新结果复用。当前不跨片段自动比较训练进步，也不做自主医疗建议。
